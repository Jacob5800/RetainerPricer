# Retainer Pricer

Dalamud API 15 plugin for pricing items in the retainer sale window.

## Use

1. Open the plugin with `/retainerpricer` or the short alias `/retainer`, from the main menu or while viewing a retainer's selling list.
2. Automatic new-item pricing and both batch actions use Universalis. A price is only suggested when there is a current competing listing of the same quality and a sale from the previous 20 days.
3. Open a retainer's sale list and click **Start listing items**. It processes all eligible carried inventory automatically: skips bound, untradeable, nonmarketable, excluded, saved gear-set, or inactive items; checks Universalis; applies the pricing rule selected in **Settings**; and confirms each new sale. Each sale is capped at 99 items; larger stacks continue in follow-up listings. Items configured on the **Batch selling** tab are split into smaller listings; other items stay as full stacks up to that cap. Items with no current price or no sale during the previous 20 days are skipped with an explanation. It stops when eligible inventory is done, the retainer's 20 slots are full, or you press **Stop**. If it cannot verify that a sale reached the retainer list, it stops before trying another item.
4. In **Batch selling**, use **Add current inventory** to add eligible carried items in one step, or add items individually. Set a maximum quantity per listing and an optional maximum total for that item in a **Start batch selling only** run. No sale exceeds 99 items; larger quantities continue in another listing if space remains. For example, a batch size of 5 and total limit of 20 lists at most 20 items in four listings; 0 means no total limit. **Start listing items** still processes all eligible inventory, using the per-listing size. **Start batch selling only** processes only configured items; all other carried inventory is ignored. Exclusions take priority, and listing stops at the normal 20-slot limit.
5. To check a price without listing, use **Price lookup** and retrieve from a captured inventory or retainer-list row. When **Automatically price and confirm new listings** is enabled, opening an eligible new sale window checks Universalis, submits the listed price, and verifies it in the retainer list. Use **Start listing items** to process all eligible carried inventory in one run.
6. To automatically reprice all retainers, click **Auto update** from the retainer picker to go top-to-bottom, or open any retainer's selling list to process that retainer first. It then visits each other available retainer once. Inactive retainers are skipped. Auto update advances the selected retainer's greeting dialogue, retrying while the Talk box remains open, then opens its options menu. It uses your price scope and exclusions, verifies every changed listing, shows the current retainer and item, and stops if the character, world, or selected retainer changes unexpectedly. **Stop** prevents further submissions; already submitted changes remain applied. This currently requires the game UI language to show the standard English retainer menu labels.
7. To reprice only the active retainer, click **Update existing listings**. It checks each eligible listing against Universalis, applies the pricing rule selected in **Settings**, submits the update, and verifies it before moving to the next item. A proposed drop beyond the configured percentage is held while the rest of the retainer is processed, then asks **Approve this price** or **Ignore**. In the **Existing listings** tab, set separate thresholds for listings under 10,000 gil (default 50%), 10,000–999,999 gil (25%), 1,000,000–9,999,999 gil (10%), and 10,000,000 gil or more (5%). Auto update uses the same thresholds and pauses at the same review for each retainer. Approval triggers a fresh quote before applying; rows show whether a price was applied or skipped for missing recent history or competition. Use **Exclude** to add an item to the persistent exception list. Changing character, world, or active retainer stops an update.
8. Use **Don't reprice** to block price changes to selected existing listings through **Update existing listings**, **Auto update**, and current-item price controls. Read-only price lookup still works, and the item remains eligible for new listings from inventory. Use **Exceptions** to skip an item from both automatic listing and repricing. Items assigned to a saved gear set are automatically protected from automatic listing, repricing, and Auto vendor; removing them from Exceptions does not override this protection.
9. In **Sniper**, choose the lookback window (3–14 days), deal threshold, minimum sales, and minimum listing value, then click **Start watching**. The configurable threshold defaults to **91.0%** of the median. Ordinary deals below the minimum per-item value are hidden; new 1-gil listings always bypass this filter and remain highlighted once per item, world, and quality. The scan follows your market scope: your home world by default, the full Data Center when **Use lowest price in the Data Center** is on, or the selected region scope when **Use lowest price in region** is on. It scans every marketable item in Universalis history batches of up to 100 item IDs, with at least one second between batch requests, then listens for new listings across the same scope. Click the **Server** column header to group deals by server; click **Listing** to sort prices ascending or descending. A listing becomes a deal when its unit price meets the minimum value, is at or below the chosen percentage of its same-quality median sale price, and that quality has at least the configured number of sales in the chosen window. The API returns up to 1,800 recent sales per item for this all-item scan. Later updates refresh an existing 1-gil alert instead of adding duplicate rows. Alerts are informational; purchases remain manual. Use **Stop watching** to cancel the scan or disconnect the feed.
10. In **Auto vendor**, open an NPC vendor's Shop window, set the maximum market price (default **1 gil**), and click **Start vendoring**. The plugin checks eligible carried items with Universalis and sells a whole stack only when a complete matching HQ/NQ listing set is available and the lowest competing price is at or below your threshold. In the **Auto vendor list**, add items individually or use **Add current inventory**; these items bypass the market-price check and threshold. Exceptions, saved gear-set, bound, untradeable, and nonmarketable items remain protected. The plugin checks the inventory change before continuing. Vendor sales cannot be undone, so review the threshold, list, and exclusions first; use **Stop** to halt further sales.
11. In **Ventures**, opt in with **Run ventures**, choose whether idle retainers get Quick Exploration and whether completed ventures repeat, then click **Start venture cycle** with the retainer picker open at a summoning bell. The cycle collects completed ventures, optionally repeats them, and optionally assigns Quick Exploration to idle retainers. It skips unavailable and in-progress retainers. It uses Retainer Pricer's own game UI controls and does not require AutoRetainer. **Stop venture cycle** halts the run and leaves the current game window open.

Prices compare HQ and NQ separately, exclude all of your retainers, and either match the lowest usable competing listing or target one gil below it, according to the **Pricing rule** in **Settings**. Existing-listing repricing uses configurable price-drop review bands based on the current listing price: 50% below 10,000 gil, 25% from 10,000 to 999,999 gil, 10% from 1,000,000 to 9,999,999 gil, and 5% at 10,000,000 gil or more by default. Change the percentages in the **Existing listings** tab; Update existing listings and Auto update share them. A proposal beyond its band is held for a user decision after the rest of that retainer's scan; approval fetches a fresh quote and ignore leaves the listing unchanged. Inventory snapshots read the four carried inventory bags; bound gear (detected from spiritbond), untradeable items, and items without a marketboard search category are skipped automatically. The optional maximum-age filter is off by default. Use the **Exceptions** tab to grab carried inventory, filter item names, select an item from the dropdown, and add or remove persistent exclusions. The picker hides items already excluded; use **Add current inventory** to exclude all marketable items in your carried inventory at once. The separate **Don't reprice** tab blocks plugin price changes to selected existing listings through automated repricing and current-item controls; read-only lookups still work, and those items remain eligible for new listings. Excluded items remain visible in the list with a **Remove** button, while manual price lookups remain available. On-screen price checks and automatic batches use Universalis. Automated runs stop if the character disconnects, begins loading or logging out, changes character or world, or the active retainer/item/menu transition cannot be verified; an item without a usable price is skipped. If **Start batch selling only** is clicked before adding any items to the **Batch selling** tab, the plugin shows “Batch selling list is empty.”

Successful Universalis responses are cached in memory for 5 minutes by default, keyed by market scope and item. Change the cache window or turn it off in **Settings**; the optional price-upload age filter remains independent. **Use lowest price in the Data Center** is an optional setting, off by default; when enabled, Universalis pricing uses all listings on the home world's Data Center. **Use lowest price in region** is a separate optional setting, also off by default; it checks every Data Center in the home world's region and includes Oceania (Materia), and applies to automatic pricing and manual lookups. The Data Center and region options are mutually exclusive. **Show button in server info bar** is an optional setting, off by default; when enabled, the **RP** button beside the game's world and time display opens Retainer Pricer. The **On-screen price check source** selector offers Universalis. Per-item batch sizes affect new listings only; the batch-only total cap limits how much of that item is listed during one batch-only run. Existing listings are repriced without changing their quantities. The plugin version appears at the bottom-left of the menu.

Universalis requests for pricing are on demand and limited to the selected item and configured market scope. Sniper loads the chosen 3–14-day history window for every marketable item in batches of up to 100 IDs, spacing history-batch requests at least one second apart, then watches new listings on the same home-world, Data Center, or region scope. Up to 1,800 recent sales per item are used to calculate separate HQ/NQ medians; highly traded items can have additional older sales omitted by that per-item limit. New 1-gil listings are always flagged even when they are below the configured minimum listing value. Alerts never buy items. Auto vendor uses the same configured price scope for threshold items; items on its separate list bypass price checks, while Exceptions and other item protections still apply. The plugin does not upload player or market data.

## Install

In Dalamud Settings → Experimental → Custom Plugin Repositories, add `https://raw.githubusercontent.com/Jacob5800/RetainerPricer/main/repo.json` for installer updates.
